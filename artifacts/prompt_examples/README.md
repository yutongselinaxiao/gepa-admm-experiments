## What a perplexity filter does

The three projections are three strengths of fluency constraint: **Euclidean** = none, **top-p** = a hard per-token constraint (only tokens in the LM's 99% nucleus), **beam λ** = a soft NLL penalty on the whole slot. A *post-hoc* perplexity filter instead lets the search run unconstrained and discards disfluent results afterwards. The tables show why that fails for Euclidean ADMM: its helpful edits are the disfluent ones, so the filter throws away the gains. The constrained projections find gains among fluent edits instead.
